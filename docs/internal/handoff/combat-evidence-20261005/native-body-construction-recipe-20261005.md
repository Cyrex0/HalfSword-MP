# Exact native body construction and rotation investigation

Status: primary-asset/source evidence and an unused read-only diagnostic. No production replacement, constraint widening, physics-asset rebuild or native construction smoke has been performed for this batch.

## What the measured rejection establishes

The parent investigation reports proxy-to-owner orientation errors of about 31 degrees for peer 1 hit 47 lowerarm_r and 59.65 degrees for peer 2 hit 142 hand_r, remaining far apart across a 400 ms owner-pose window. These establish a displayed-body mismatch, not its solver cause. The 183.7 cm cutting-box lever in the first case amplifies a modest limb rotation into a large reconstructed box error.

Current `BF.of` and both servo implementations use `GetSocketTransform(bone, World)`. `PURE.fk_retarget[_in]` alters positions only and preserves target quaternions. There is no explicit conversion to a different physics-body orientation basis in those paths. Nevertheless, a stale socket or a native body/socket basis difference remains unmeasured and must be distinguished from solver limits.

Current `PX.open_limits` defaults to zero (native limits preserved), despite its obsolete comment saying 150. The source records earlier measured owner grip poses exceeding wrist/elbow limits and stable angular stalls. The re-pose path is suppressed near combat. This is a plausible mechanism, not proof that these particular contacts are joint-limited. Do not restore broad opened constraints to make the test pass.

The preserved current run log is `test-results/20261005-134221-29e054-combat_manual/astra-servo-review/UE4SS-preserved.log`. For example, at 13:43:28.648 the proxy of peer 1 reports maximum lowerarm_r rotation error 40.64 degrees; at 13:43:29.302 peer 2 reports maximum hand_r rotation error 89.85 degrees. Those are measured versus each local servo target, independently corroborating a real servo-tracking error. They do not identify the physics limit or prove timing alignment for a particular claim.

## Joint dictionary and diagnostic boundaries

`body-primary-joint-dictionary.json` contains the exact PhysicsAsset path, 22 body identities and 21 constraints: `UserConstraint`, `UserConstraint_0` through `_19`, including both endpoint bone names, Pos1/2, PriAxis1/2, SecAxis1/2, angular offset where serialized, default ProfileInstance and named profiles. Missing serialized fields mean inherited native defaults, not zero values.

Examples demonstrate why selecting the wrong profile is material: the lowerarm_r joint `_11` has default twist 90 degrees versus Motor twist 30; hand_r `_12` has Motor swing1 45 / twist85; clavicle_r `_9` changes default swing1/twist30 to Motor10/10. The left-side equivalents are `_15`, `_16`, `_13`. Do not compare a runtime Motor joint against the default profile and call it corrupt.

The reflected SDK exposes `SkeletalMeshComponent:GetCurrentJointAngles`, `GetConstraintByName` and `ConstraintInstanceBlueprintLibrary:GetAttachedBodyNames/GetAngularLimits/GetLinearLimits/GetAngularDriveParams`. It does not expose a complete skeletal joint frame getter in that library. Asset frames can be copied into a manifest, but runtime frame equivalence after scale/construction cannot be asserted from profile readback alone. Any later Body3 proposal must distinguish native asset dictionary/frame definitions from measured dynamic overrides and broken/missing joints; it must not reset an injured body to an intact dictionary.

Unused module `mods/dev/HSMPParity/Scripts/body_frame_probe.lua` provides a bounded synchronous capture of socket frame, PhysicsObjectWorldTransform, COM, actual mass, angular velocity, current joint angles, optional actual servo target and 21 named runtime profiles. It verifies constraint endpoints and original context before/after capture; failures remain explicit. It returns only copied scalars, never native wrappers. Pinned UE4SS `LuaUObject.cpp` proves scalar out tables use parameter-name keys, struct by-ref inputs require tables, and native FWeakObjectPtr values can be copied unchanged; no guessed offsets are used. The new module has 13 focused fixtures but has not run natively. The physics body's relationship to the bone socket remains labelled unverified.

## Concrete discriminating native reproduction

Capture source and proxy for lowerarm_r/hand_r, their parents and neck/head in the same callbacks as current servo target publication, including original context and display label. Read native current angles and runtime Motor/default limits in the same capture. At rest, with the original polearm held, and during an automated repeatable normal animation/input pose, compare:

* socket versus physics-body rotation: detects stale socket/body basis divergence;
* proxy socket versus actual target and owner timestamped socket: separates driver timing from tracking error;
* angular correction command versus actual next-step angular velocity and current joint angles/limits: detects solver limitation;
* owner and proxy passport/shape/constraint/profile/scale: distinguishes construction mismatch from an otherwise matching body subject to different drives/grips.

Then repeat in an isolated fresh native body built from the same immutable passport and normal delayed setup. Success means matching native state and reduced measured error without broad constraint or hit-tolerance changes. Until that comparison runs, native construction mismatch is a strong candidate, not the established cause of all 73 rejects.
