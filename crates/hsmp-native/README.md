# hsmp-native: HSMPNative, the game side of HSMP-SHM

The game-side shared-memory client and Lua binding (design and Lua API contract:
`docs/development/ipc-shared-memory.md`). One Rust implementation (`src/`), shipped two ways:

| Option | Artefact | Loaded by | Entry |
|---|---|---|---|
| **F** (default) | `Mods/HSMPNative/dlls/main.dll` | UE4SS as a C++ mod | `on_lua_start` → `hsmp_native_open(L, mod)` → global `HSMPNative` in every `HSMP*` Lua mod, before its main.lua runs |
| **E** (fallback) | `Mods/HSMPNative/dlls/hsmp_lua.dll` | the Lua facade: `package.loadlib("<Mods>/HSMPNative/dlls/hsmp_lua.dll", "luaopen_hsmp_lua")` | returns the API table; if F already registered `HSMPNative` in that state, returns **that** table |

Rules the binding follows: no threads, no sockets, no UObject access outside native sampling / servo (`sample.rs`, `servo.rs`, `neutralise.rs`); every call is non-raising
(`nil, "msg"`), panic-safe (a caught panic poisons IPC for the session: `nil, "disabled"`) and
game-thread checked (captured at the first `frame()`; other threads get `nil, "wrong thread"`).
The IPC state is process-global, so it survives UE4SS "restart all mods" (`game_lua_gen` + 1).

**Load E from exactly one absolute path.** Every distinct DLL path is a distinct module instance
with its own process-global state; a second copy refuses `ipc_open` with
`"ipc owned by another native copy in this process"` (so a process never has two G2S producers).

Contract notes (truthiness-compatible with the documented Lua API): `peer_play` sets `out.root` and
`out.C` to `false` (not `nil`) when absent, so the keys stay live and the reused table never
rehashes; extra fields on the API table: `_impl` (`"F"`/`"E"`), `version`, `ABI_MAJOR`,
`LAYOUT_HASH`, and in F `lock_mode`, `ue4ss`. `hsmp_native_open` takes the mod name as a second
argument (C++ passes it; used for reload detection).

## Layout

| Path | What |
|---|---|
| `src/` | Rust staticlib: `api.rs` (entry points, guards, registration), `native.rs` (segment client, event log + per-state cursors, caches), `records.rs` (typed record API: put / get / peer / send / poll data / typed bus keys / world-leave invalidation, by schema name), `marshal.rs` (Lua table ↔ record bytes, generic over `TypeDesc`; spec: `lua-tests/lib/hsmp_native_records.lua`), `pose_hot.rs` (put_root / put_weapon / put_pose / put_lead), `dev.rs` (DevCtl fan-out: `dev_poll`), `proc.rs` (spawn / proc_* / spawn_capture / capture_poll / current_pid), `reflect.rs` + `sample.rs` (native sampling: sample_config / sample_local / sample_status), `servo.rs` + `neutralise.rs` (native servo: servo_bodies / servo_weapon / neutralise), `lua.rs` (raw Lua 5.4.7 FFI) |
| `tests/records.rs` | `cargo test`: the shared conformance script `lua-tests/lib/records_conformance.lua` (also run against the Lua mock by `hsmp-tools lua-test records`) on the real module with test-only records, DevCtl fan-out, argv quoting, capture; `--release -- --nocapture` prints the typed-record timings |
| `tests/api.rs` | `cargo test`: the whole API against an in-process fake sidecar on the real named mapping (Lua from mlua's vendored 5.4); allocation check; `--release -- --nocapture` prints per-call timings |
| `fake-sidecar/` | `hsmp-fake-sidecar.exe`, test-only cross-process sidecar stand-in for the harness |
| `cpp/src/dllmain.cpp` | the UE4SS C++ mod (CppUserModBase replica, registration only, refuses an un-pinned UE4SS.dll) |
| `cpp/src/ue4ss_reflect.cpp` | engine reflection for native sampling / servo: resolves 23 RC::Unreal exports of UE4SS.dll with GetProcAddress (pinned build only; weak handles come off the object array, never FWeakObjectPtr) into the vtable `src/reflect.rs` consumes; `cpp/test/reflect_check.cpp` checks the names against a UE4SS.dll (`-DUE4SS_DLL=<game>/.../UE4SS.dll` adds the real-build test) |
| `cpp/src/hsmp_luauser.c` | lua_lock forwarding to UE4SS's own LuaLock (pinned build) + Lua ABI size asserts + C-compiled-Lua check |
| `cpp/abi/` | `ue4ss_abi.hpp`, `UE4SS.def`, `ue4ss_pins.h` (generated by the `ue4ss_pins` tool, plus the `HSMP_UE4SS_LUA_COMPILED_AS_C` pin) |
| `cpp/gen/hsmp_ipc.h` | generated by `hsmp-tools gen-ipc`; compiled as C11 and C++20 with `/W4 /WX` by the CMake build |
| `cpp/test/` | `harness.exe` (mock UE4SS.dll, raw-vtable dispatch, modes F and E) + `harness_ipc.lua`, `harness_sample.lua` |
| `probe/HSMPNativeProbe` | dev-only in-game probe: prints `IPC VERDICT attach=… abi=… slots=… ring=… bus=… frame_us=p50/p99` |

## Build

`cargo build -p hsmp-native` / `cargo test -p hsmp-native` need no CMake.

The DLLs and the harness (Windows, MSVC 2022, CMake ≥ 3.22, an RE-UE4SS checkout at the pinned
commit `e3ba1016` for its Lua 5.4.7 sources):

```powershell
cmake -S crates/hsmp-native -B <build> -G "Visual Studio 17 2022" -A x64 -DUE4SS_SRC=<RE-UE4SS checkout>
cmake --build <build> --config Release
ctest --test-dir <build> -C Release --output-on-failure      # harness_F, harness_E
```

Output in `<build>/out/`:

```
out/HSMPNative/dlls/main.dll           -> <game>/.../ue4ss/Mods/HSMPNative/dlls/main.dll
out/HSMPNative/dlls/hsmp_lua.dll       -> <game>/.../ue4ss/Mods/HSMPNative/dlls/hsmp_lua.dll   (E fallback, same folder)
out/HSMPNativeProbe/Scripts/main.lua   -> Mods/HSMPNativeProbe/Scripts/main.lua               (dev deploys only)
```

`mods.txt` needs `HSMPNative : 1` (a C++ mod: UE4SS loads `dlls/main.dll`; no Scripts folder).
The probe also wants `mods/shared/hsmp_ipc_schema.lua` copied into its Scripts folder to check the
layout hash. `HSMPNative.log` is written next to the `Mods` folder.

`HSMP_IPC_GAME_CAPS=<hex>` masks the capabilities the game offers (A/B runs).
`HSMPNATIVE_ALLOW_UNPINNED=1` lets main.dll register on an un-pinned UE4SS.dll (offline harness
only; never in a deploy).
